# 虚拟教研社区 — 项目故事

## 为什么做这个项目
我所在的高职院校里，英语教师们日常备课、找资料、交流教学经验主要靠微信群。群里文件过期就没了，有价值的讨论很快被刷上去，新老师想找之前的分享也翻不到。
我想做一个平台，把教研交流从碎片化的聊天记录里解放出来——帖子可以沉淀、资料可以分类检索、AI 可以辅助分析学生反馈。这是我学习全栈开发一年后的第一个完整项目，也是我对"技术能不能帮到一线教师"这个问题的回答。

## 技术选型
一开始用 Streamlit 快速搭了个原型，但它长得太像仪表盘，不像一个"社区"。后来全部推翻，用 Vue 3 重写了前端。
后端选 FastAPI 是因为它天然支持异步和 Pydantic 校验，适合我这种一个人写前后端的情况——出参入参类型写清楚，调试省很多时间。数据库用 MySQL，裸写 SQL 不用 ORM，因为我想把 SQL 学扎实。
情感分析模型是前段时间做的一个项目迁移过来的，原来训练在酒店评论上。后来我自己标注了 4350 条教学评价数据重新训练——每条标签背后不只是正负面判断，更是我对"什么样的老师是好老师"的理解。模型会特别关注实训授课、课堂互动、学困生关怀、课件质量、课后资源这五个维度，因为这些才是一线教师真正在意的东西。模型学的不只是词和标签，是我对教育行业的理解。

## 遇到的挑战
最大的坑是部署。本地跑得好好的，上了阿里云 ECS 之后各种问题——Python 版本太旧、Node.js 版本不兼容、Supervisor 环境变量不生效、Nginx 缓存导致前端不更新。那段时间几乎每天都在看日志、查文档、试错。
架构上也走过弯路。一开始数据库查询返回的是 raw dict，全链路用字符串 key 取值。后来发现密码哈希会跟着 dict 一路泄露到 API 响应里，才下决心重构——引入 DO（Data Object）和 VO（View Object）双层模型，定了三条硬规则：API 层禁入 DO、Service 层负责脱敏转换、DB 层只返回 DO。改完 29 个接口，最大的收获是理解了"分层不是为了好看，是为了让错误没有机会发生"。

## 学到了什么
最核心的不是某个具体技术，而是一个认知：**写代码和建系统是两件事**。刚开始我的关注点都在"这个功能能不能跑通"，后来慢慢转向"这个系统能不能被另一个人看懂、修改、扩展"。
Design Tokens 统一了全站颜色和间距，全局异常 Handler 消灭了 16 处重复的 try-except，连接池把查询从 30ms 降到 2ms——这些都不是用户能看到的，但它们是工程和玩具的区别。

## 下一步
这个项目还会继续维护。教研资料部的文件上传功能已经在规划中，如果未来能接上大模型 API，AI 聊天室就能从预设回复变成真正的智能问答。
